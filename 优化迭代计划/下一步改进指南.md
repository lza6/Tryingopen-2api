## 0. 结论先行（TL;DR）

当前 v0.1.12 已闭环：Rust(axum) 单二进制、OpenAI/Anthropic/Responses 三协议、代理池 44 源 4500+ 出口、限流/熔断/metrics、Web 控制面板、CI/CD 部署，fmt/clippy/53 tests 全绿、生产 healthz 200。

**从 1 → 2~999 的下一步，按「用户价值 × 落地成本」排序的 P0 清单：**

| 优先级 | 主题 | 一句话目标 | 预估批次 |
|---|---|---|---|
| P0-A | 非流式工具调用统一 + 上游 messageLimit/cheaperFallbackId 透传 | 工具体验与上游能力对齐，消除"同一模型两种行为" | B1 |
| P0-B | 一键 curl 复制 + 模型能力徽章 + 面板暗色/空态/移动端 | 降低接入摩擦，N7-P0 遗留项落地 | B2 |
| P0-C | 会话级用量/配额仪表盘（内存版）+ /v1/usage 接口 | 从"黑盒网关"变成"看得见配额的网关"，为付费/托管埋点 | B3 |
| P0-D | 请求日志结构化 + 分级审计日志（脱敏） | 生产可观测、可排障，先于任何新功能 | B4 |
| P0-E | 性能：请求全链路压测基准 + release 编译优化 + Docker 镜像瘦身 | 用数据说话，建立性能回归基线 | B5 |
| P1 | Redis 可选缓存层、上游多源聚合、白标面板 | 产品化/规模化方向（需独立评审） | B6+ |

**执行铁律（每条改动落地时必须遵守）：**
1. 先读本指南对应批次 + `docs/audit/*` 台账，防重复修已知问题。
2. 改动后必须跑 `cargo fmt` → `cargo clippy -- -D warnings` → `cargo test --lib --tests`，全绿才算过门禁。
3. 新增行为必须配测试（当前 53 tests，目标是行为覆盖不下降、尽量提升）。
4. 面板改动需真实验证：`cargo run --release` → 浏览器打开 `/ui` → 走真实用户路径（点击、反馈、错误态、空态、移动端）。
5. 每次发布前：更新 `Cargo.toml` 版本 → `CHANGELOG.md` → `README.md` → `docs/INDEX.md` → `docs/API_CONTRACT.md` → `config.example.json` → `workflow_status.md`，版本/测试数口径全仓统一。
6. **不重构**：只做小步、可回滚、可单测的行为级改进；大改架构需先写 ADR 并经你确认。
7. 交付即闭环：不许"只写文档不实现"、不许 TODO 占位、不许没跑验证就声称完成。

## 1. 项目现状盘点（基线证据）

### 1.1 技术栈与架构

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | Rust 2021 edition | 单二进制，`Cargo.toml` 无 rusqlite（已移除死依赖） |
| Web 框架 | axum 0.8 | 路由 + JSON + SSE 流式 |
| HTTP 客户端 | reqwest 0.12 | rustls、gzip/brotli、socks、stream |
| 异步 | tokio full | 并发代理预检、后台刷新任务 |
| 协议 | OpenAI chat / Anthropic messages / Responses | `src/protocol/` 三套 SSE 转换 |
| 前端 | 单 HTML 内嵌（无构建） | `src/web.rs` 的 `INDEX_HTML` 字符串 |
| 测试 | 53 个（models_test + proxy_test + 各模块内嵌单测） | 含限流/熔断/metrics/日志脱敏/truncate 行为测试 |

- 安全：16MB 请求体限制、SSRF 公网地址过滤、日志脱敏、/metrics 鉴权、密钥管理上限

## 3. 执行规划（批次任务分解 + 验收矩阵）

> 原则：**一次只动一个主题批次**，每批独立可测可回滚。以下每批给出「目标 / 改动文件 / 测试要求 / 验收方式 / 回滚」。

### 批次 B1：协议对齐（A1+A2+A3，对应 L1/L2）

**目标**：上游 messageLimit/cheaperFallbackId 透传 + 非流式工具调用双协议一致性。

- 改动文件：`src/models.rs`（模型字段扩展）、`src/api.rs`（非流式工具调用分支复核）、`src/upstream.rs`（目录解析透传）、`docs/PROTOCOL.md`、`docs/API_CONTRACT.md`
- 测试要求：
  - 新增单测：messageLimit/cheaperFallbackId 解析与透传（≥2 个）
  - 非流式 tool_call 检测 → `finish_reason:"tool_calls"`（OpenAI + Anthropic 各 1）
  - 上游 429 + cheaperFallbackId → 自动换降级模型（1 个，mock 层）
- 验收：`cargo test --lib --tests` 全绿（53 → ≥57）；本地真实上游非流式工具对话 1 次（带 key）；README 测试数同步
- 回滚：单 commit 可 revert；文档同步在一个 commit

### 批次 B2：面板体验（U1+U2+U5，对应 L3）

**目标**：一键复制示例 + 模型能力徽章 + 轮询合并。

- 改动文件：`src/web.rs`（INDEX_HTML 内嵌前端）
- 测试要求：
  - 前端无单测框架（内嵌字符串），验收走**真实浏览器**：打开 `/ui`，点击"复制 curl"，剪贴板内容含 base_url+key+模型；模型表徽章渲染正确；移动端 375px 视口下按钮可点、表格可横滑
  - 后端侧：新增 `GET /api/guide` 响应字段单测（若需加字段，同步 API_CONTRACT）
- 验收：浏览器截图/console 无报错；`cargo test` 全绿
- 回滚：web.rs 单文件改动，git revert 即可

### 批次 B3：用量与配额可见性（O2+M1 第一步，对应 N7-P1）

**目标**：每 key 用量统计 + `/api/usage` + 面板"用量"页。

- 改动文件：`src/prod_guard.rs`（用量环形缓冲）、`src/api.rs`（/api/usage 路由）、`src/web.rs`（用量页）、`docs/API_CONTRACT.md`
- 测试要求：
  - 每 key 计数：请求数/429/耗时分桶/代理出口数（≥3 个单测）
  - 环形缓冲上限（如 4096）与 key 上限一致，防无界内存（1 个）
  - 鉴权：/api/usage 与 /api/* 一致（1 个）
- 验收：本地 curl /api/usage 带 key 返回 JSON；面板用量页真实渲染；`cargo test` 全绿
- 回滚：路由+状态独立，可整体 revert

### 批次 B4：结构化日志（O1，对应生产排障）

**目标**：请求日志 JSON 化 + 脱敏分级。

- 改动文件：`src/prod_guard.rs`（或新建 `src/logging.rs`）、`src/api.rs`（接入点）、`src/config.rs`（log_level/log_json 配置）、`config.example.json`
- 测试要求：
  - JSON 日志含必填字段且 key 脱敏（≥2 个单测）
  - 中文/多字节 body 截断不 panic（1 个，防 D1 类 bug 回归）
  - 开关 `redact_logs` 行为不变（1 个）
- 验收：本地发 1 个请求看 JSON 日志行；`cargo test` 全绿
- 回滚：独立模块 + 开关默认关闭，安全

### 批次 B5：性能基线与编译调优（P1+P2，H1 同批）

**目标**：建立压测基线 + release 编译参数实测。

- 改动文件：`Cargo.toml`（profile 调优）、`scripts/bench/`（新增压测脚本）、`docs/audit/N3-benchmark-2026-09-2X.md`
- 测试要求：
  - 压测脚本可重复运行，输出 JSON 基线
  - 对比 lto thin/fat、codegen-units、panic abort 的体积/耗时差异（记录实测）
- 验收：基线 JSON + 报告落盘；`cargo test` 全绿
- 回滚：Cargo.toml profile 改动 revert 即恢复

### 批次 B6+：P1/P2 方向（独立评审后再做）

- Redis 缓存层、多上游聚合、白标面板、告警通知、Docker 瘦身 —— 每一项先写 ADR/方案文档（本目录新增 `方案-<主题>.md`），你确认后再实施。

## 6. 风险与边界（诚实提示）

1. **上游是匿名免费服务**：`每 24h UTC 日约 20 次` 是硬约束，任何自动化压测/批量调用都会打满配额。压测必须走代理池且控制总量，或使用 mock 上游。
2. **免费代理不可靠**：明文 HTTP、存活率波动，生产高并发建议住宅代理文件；面板/日志需持续观测代理池水位。
3. **工具调用是提示词式**：模型"可能不调用工具"，这不是 bug，客户端必须容忍文本回复。
4. **历史凭据重写（L6/F9）**：涉及 git 历史改写，默认不做；需你明确授权 + 全组同步 + 轮换所有凭据后才执行。
5. **生产部署是真实资源**：CD 自动部署到 20.204.27.154，任何改动先本地全量验证再 push main；push 前确认工作区干净、无未提交源码。
6. **面板内嵌字符串无构建链**：改动 web.rs 必须真实浏览器验证，不能只看字符串拼写。
